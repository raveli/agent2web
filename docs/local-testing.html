agent2web · Runbook Local testing · macOS · Node 22

Running it on your laptop.

Everything except the Claude web connector can be exercised locally, including subdomain hosting and the full MCP publish flow. Eight steps, about five minutes.

You need: Node 22 or newer and this repository. Nothing else — no database, no Docker, no DNS entries. Data lands in ./data, which is gitignored.

01

Install and run the test suite

The suite boots a real server on an ephemeral port for most of its cases, so a clean pass also proves your machine can run the app.

npm install npm test
Expect
# tests 79 # pass 79 # fail 0
02

Generate secrets and write .env

Print a set of credentials and paste them into .env. Save the admin password it shows — it is not stored anywhere else.

npm run gen-secrets

Then create .env with those values plus the local settings:

A2W_PUBLIC_URL=http://localhost:8080 A2W_SECRET=<generated> A2W_ADMIN_PASSWORD_HASH=<generated> A2W_API_TOKEN=<generated> A2W_DATA_DIR=./data A2W_PORT=8080 A2W_TRUST_PROXY=false A2W_SITES_BASE_DOMAIN=sites.localhost
Why sites.localhost macOS resolves any *.localhost name to 127.0.0.1, so subdomain hosting works with no DNS setup. Leave the port off this value — it is a hostname, and the app appends its own port when it builds URLs.
03

Start the server

npm start does not read .env by itself, so export it first. (docker compose up loads the file directly if you prefer that.)

set -a && . ./.env && set +a && npm start
Expect
[agent2web] listening on 0.0.0.0:8080 [agent2web] public URL http://localhost:8080 [agent2web] MCP endpoint http://localhost:8080/mcp [agent2web] sites at http://localhost:8080/s/<slug>/ and http://<slug>.sites.localhost:8080/

Bad configuration stops the process here with the reason, rather than half-starting. In another terminal:

curl -s localhost:8080/healthz
{"status":"ok","sites":0,"version":"0.1.0"}
04

Publish a page

This is the same call Claude makes. Export A2W_API_TOKEN from your .env first.

curl -s localhost:8080/mcp \ -H "authorization: Bearer $A2W_API_TOKEN" \ -H 'content-type: application/json' \ -H 'accept: application/json, text/event-stream' \ -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{ "name":"site_publish", "arguments":{"slug":"hello","html":"<h1>Hello from agent2web</h1>"}}}'
Expect (inside the JSON-RPC result)
Published **hello** (1 file, 29 B) http://hello.sites.localhost:8080/ Also at: http://localhost:8080/s/hello/
Gotcha The accept header must list both application/json and text/event-stream. That is the MCP spec, not a quirk of this server — omit either and you get 406 Not Acceptable.
05

Compare the two URL forms

Both addresses serve the same site at the same time. The difference is worth seeing, because it decides how you deploy.

open http://localhost:8080/s/hello/ # path-based open http://hello.sites.localhost:8080/ # subdomain

Publish a page that loads /style.css and the subdomain version resolves it; the path version returns 404, because the site is not at the origin root. Pages served from the app's own origin also get a sandbox CSP that gives them an opaque origin, so they cannot reach your admin session. On their own subdomain they do not.

06

Password-protect it

curl -s localhost:8080/mcp \ -H "authorization: Bearer $A2W_API_TOKEN" \ -H 'content-type: application/json' \ -H 'accept: application/json, text/event-stream' \ -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{ "name":"site_set_access", "arguments":{"slug":"hello","visibility":"password","password":"open-sesame"}}}' curl -s -o /dev/null -w "%{http_code}\n" localhost:8080/s/hello/ curl -s -o /dev/null -w "%{http_code}\n" -u :open-sesame localhost:8080/s/hello/
Expect
401 ← the unlock form 200 ← HTTP Basic works, for scripts

In a browser you get a form instead. Changing the password later invalidates every unlock cookie already issued.

07

Open the admin UI

Sign in at localhost:8080/admin with the admin password from step 02. The list shows what is published and who can reach it; selecting a site opens its own page for access, custom domain, versions, files and deletion.

08

Connect a real client

Both credentials work locally. The static token skips the browser entirely; the OAuth flow uses a loopback callback, which the redirect policy allows on any port.

npx @modelcontextprotocol/inspector # then point it at http://localhost:8080/mcp claude mcp add --transport http a2w-local http://localhost:8080/mcp \ --header "Authorization: Bearer $A2W_API_TOKEN"
Not testable locally Claude web custom connectors need a public HTTPS URL with a certificate a browser trusts, so that flow cannot run against localhost. To try it before deploying, expose the port with cloudflared tunnel --url http://localhost:8080 and set A2W_PUBLIC_URL to the tunnel hostname — it must match exactly, since it is the OAuth issuer and the audience of every token issued.

When it misbehaves.

Every row here is a failure we actually hit while building this, with the symptom that showed up first.

SymptomCause and fix
Admin login says Incorrect credentials with the right password An older $-separated password hash sourced unquoted from .env: the shell expands $16384 and friends, silently corrupting it. Regenerate with npm run gen-secrets — current hashes are dot-separated and shell-safe. The app now refuses to start on an unparseable hash rather than failing at the login form.
406 Not Acceptable from /mcp The accept header must list both application/json and text/event-stream.
Startup fails on a missing variable although .env has it npm start does not load .env. Use set -a && . ./.env && set +a, or run via docker compose.
Subdomain URLs 404, or point at the wrong port A2W_SITES_BASE_DOMAIN must be a bare hostname with no port and no leading dot — sites.localhost, not sites.localhost:8080.
A code change appears to do nothing npm start runs the compiled output in build/. Rerun npm run build and read its output — a failed build leaves the previous version running and looks exactly like a change that had no effect.
Port 8080 already in use An earlier run is still alive: pkill -f "build/src/index.js", or set A2W_PORT and A2W_PUBLIC_URL to another port together.
Starting over Stop the server and rm -rf ./data. The schema is recreated on the next boot; published sites and OAuth clients are gone.
